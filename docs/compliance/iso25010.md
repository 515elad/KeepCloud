# ISO/IEC 25010 product quality mapping

KeepAir is built to be **aligned with** ISO/IEC 25010. This is not a certification and no certification is claimed. Updated at the end of each phase.

Status after phase 2.

| Characteristic | What phase 0 provides | Evidence | Gaps |
|---|---|---|---|
| Functional suitability | Budget hierarchy and effective remaining (FR-04); vendor and model registry with block precedence and default deny (FR-18); block cascade and coverage badge in the UI. Correctness is checked with property tests over all status combinations and random budget trees. | `tests/unit/test_budgets.py`, `tests/unit/test_registry.py`, `tests/system/test_budgets_pages.py`, `tests/system/test_gateway_registry.py` | Also: the gateway request path with reserve, dispatch and settle (FR-05), idempotency, denial contract, credentials, denials feed (`tests/integration/test_gateway_*.py`, `test_ledger.py`). Not built: streaming, fail-open spool (phase 3), spend data (4), approvals (5), audit log (6). |
| Performance efficiency | Target: gateway adds at most 25 ms p95 before dispatch (PRD v1.4 Section 2.4). Measured in the test environment: a full round trip, reserve to settle, at about p50 29 ms and p95 34 ms. 200 concurrent reservations complete without deadlock. | `test_gateway_overhead_is_measured`, `test_reserve_never_exceeds_cap_under_200_concurrent_requests`, `test_opposite_paths_do_not_deadlock` | The target is not shown to be met: the measurement is not the same quantity and not a pilot environment. |
| Compatibility | Runs as one container next to PostgreSQL 16; `/metrics` uses the Prometheus text format. | `docker-compose.yml`, `test_liveness_and_metrics_endpoints` | OpenAI-compatible gateway shape in phase 2. |
| Usability (incl. accessibility) | Every field has an "i" with meaning, unit, source, formula, worked example, range and PRD reference. Status always has an icon and a word. Keyboard access, visible focus, skip link, light and dark themes, layout ready for RTL. Aligned with WCAG 2.2 AA. | `test_field_help.py`, `test_accessibility_basics`, manual browser check (`docs/testing/test-plan.md`) | No automated contrast or screen-reader test yet. |
| Reliability | A database outage does not take the UI down: health shows Unknown, a notice and an alert appear. In the gateway, every failure path closes the money side: timeouts settle at the reserved amount, unused reservations expire, a failed transaction leaves nothing behind, and a ledger outage refuses requests. Heartbeats make a stopped gateway visible. | `test_failure_visibility.py`, `test_ledger.py`, `test_gateway_operations.py` | Fail-open spool and recovery in phase 3. Restore drill not done. |
| Security | See `iso27001-annex-a.md`. Strict Content-Security-Policy, no inline script or style, autoescaped templates, hash-pinned dependencies, secret scanning, non-root container. | `test_security_headers_on_every_response`, `test_secret_scanner.py` | No sign-in until phase 5; the app is published on localhost only. Cross-site form posts are refused. Row-level security is not on yet (A-25). |
| Maintainability | Clock and randomness injected; help text in one registry; formulas checked against code; lint in CI; every test names its requirement. | `test_no_wallclock.py`, `tests/conftest.py`, `.github/workflows/ci.yml` | Mutation-testing gate (FR-21) not set up. |
| Portability | Docker image on `python:3.12-slim`; configuration through `KEEPAIR_*` environment variables; migrations with Alembic, tested up and down. | `Dockerfile`, `test_migration_downgrade_and_upgrade_round_trip` | Image not yet built on an ordinary network (see `docs/lifecycle/phase-0.md`). |
