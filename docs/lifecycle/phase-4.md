# Phase 4: Spend data, allocation and reconciliation states

Lifecycle record, aligned with ISO/IEC 12207 (plan, entry and exit criteria, review).

## Plan

**Scope.**

- Ingest billing files: CSV in a FOCUS-style column layout, generated by the demo seed (no real provider data). Idempotent by (source, record key, revision). A corrected record arrives as a new revision; the old one is kept and marked superseded.
- A billing file is untrusted input (SEC-28): size, row and column limits, strict field parsing with exact decimals, an allowlist for tag keys. A file with any invalid row is quarantined as a whole and nothing is loaded.
- Allocation of billing records to projects (FR-03): directly from tags, by a rule that splits shared cost, by a fallback join, or by hand. Confidence is DIRECT, INFERRED or MANUAL. Every record is allocated or explicitly unallocated or unmatched.
- Join confidence (FR-06): exact match 90 to 100, fallback 70 (flagged for review), below 70 unmatched.
- Finalization state on every total (FR-07, UX-8): ESTIMATED (gateway), PROVIDER_REPORTED, INVOICED. Figures of different states are never added together. Estimated uses a hatched pattern.
- Spend page: totals by state, cost explorer with small multiples by model, allocation by project, queue of unallocated, unmatched and review records with manual assignment, upload and ingestion history.
- Reconciliation page: estimate against provider figures by period and by project, gateway-controlled share, uncontrolled-spend findings (FR-19).
- Demo: upload a demo billing file and watch the pages change; one unmatched record and one join in the 70 to 89 band.

**Out of scope.** Real cloud or provider connectors, PDF invoices, ERP, period close and locking, anomaly detection, forecasts, FX conversion of billing data (billing and gateway cost are compared in the price currency), CSV export (phase 6).

**Risks.**

| Risk | Handling |
|---|---|
| The same file loaded twice doubles the spend | Unique key (source, record key, revision); a repeat is counted as unchanged. Test. |
| An estimate is shown as an invoice | A figure carries its state; adding different states raises; each billing source may only supply its own state; gateway figures are ESTIMATED by construction. Tests. |
| Gateway cost and provider cost are added together | They are shown side by side, never summed. |
| A malicious or broken file harms the system or the numbers | Limits before parsing, strict parsing, all-or-nothing load, quarantine with an alert. Fuzz test on the parser. |
| Rounding loses or invents money when a cost is split | Largest-remainder method on integer micro-units; property test that shares add up exactly. |
| A tag assigns cost to the wrong project silently | Fallback joins are capped at confidence 70 and listed for review; no match is never guessed. |

**Notes.**

- **Found by the tests and fixed.** (1) The ingestion history stored zero for New, Revised and Unchanged, because the batch row was written before the rows were counted. (2) Uncontrolled spend was first raised for two projects that only received rule-split shared cost; per-project comparison now uses only cost tied to the project itself (A-66). (3) The registry's own rule rejected a help text of three sentences. (4) The "Reason" input in the queue had no "i" next to it; it now has its own column.
- **Scope added beyond the brief's list.** Uncontrolled-spend detection (FR-19) with the Uncontrolled coverage badge, a period summary on Overview, and the Reconciliation page. They fall out of the same data and the earlier pages had promised them.
- **Not built, and said so in the UI.** Allocation rule editor, cloud connectors, invoice PDFs, period close, forecasts and anomaly alerts. Each is listed as "Not in the MVP phases" on its page.
- V-1 (how real providers report usage) is still not verified. Nothing in this phase depends on it, and nothing here should be read as a statement about a real provider's export.
- Assumptions A-57 to A-71 were recorded. A-60 (states are never merged into one "best" total) and A-66 (what counts as uncontrolled) deserve the owner's review.
